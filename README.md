# VetMoment

Сервис помощи бездомным животным и приютам Казахстана: **анкеты питомцев, сбор пожертвований, запись на выгул**.

Стек: Laravel 13 (PHP 8.4), Blade, Tailwind CSS 4 + Vite, PostgreSQL 15, Docker Compose.
План разработки и статусы этапов — [`docs/PLAN.md`](docs/PLAN.md).

Что внутри: каталог питомцев с фильтрами и заявками «Хочу забрать», сборы с онлайн-пожертвованием (демо-банк) и отчётами,
запись волонтёров на выгул по слотам, кабинеты волонтёра, приюта и администратора, уведомления на сайте и по почте.

## Запуск на Windows за 3 шага

Нужен только **Docker Desktop**. PHP, Composer, Node.js и PostgreSQL ставить не нужно — всё собирается внутри Docker.

1. **Установите Docker Desktop** — <https://www.docker.com/products/docker-desktop/>.
   При установке оставьте галочку «Use WSL 2», после установки перезагрузите компьютер и один раз
   откройте Docker Desktop (дождитесь надписи «Engine running»).
2. **Скачайте проект**: на GitHub кнопка **Code → Download ZIP**, распакуйте архив
   (или `git clone`, если установлен Git).
3. **Дважды кликните `start.bat`** в папке проекта.

Первый запуск занимает 5–10 минут (скачиваются образы, собирается приложение), следующие — секунды.
Когда всё готово, браузер сам откроет **<http://localhost:8000>**. База данных уже создана и заполнена
демо-данными.

Остановить — `stop.bat` (данные сохраняются).

### Демо-доступ

Вход — <http://localhost:8000/login>, по логину или телефону; пароль у всех демо-пользователей — `password`.
После входа откроется кабинет по роли. Уже работают: каталог питомцев <http://localhost:8000/pets> с фильтрами,
карточка питомца, заявка «Хочу забрать» / «Взять под опеку», избранное (`volunteer` → «Избранное»), анкеты и
заявки в кабинете приюта (`shelter` → «Питомцы», «Заявки»); сборы <http://localhost:8000/campaigns> с формой
пожертвования (можно без входа), «Мои пожертвования» (`volunteer`), сборы, отчёты и пожертвования приюта с выгрузкой
в CSV (`shelter` → «Сборы», «Пожертвования»); запись на выгул <http://localhost:8000/walks> (приют и время →
подтверждение → запись, отмена, файл для календаря), «Мои выгулы» (`volunteer`), слоты, шаблон недели и записи
приюта с подтверждением и отметками «Состоялся» / «Не пришёл» (`shelter` → «Слоты выгула», «Записи на выгул»).
Кабинеты завершены (этап 11): обзор и «Мои заявки» волонтёра, профиль и смена пароля (`volunteer`), сводка и профиль
приюта (`shelter`), админка (`admin`): статистика по месяцам, очередь модерации приютов, скрытие анкет и сборов,
заявки, блокировка пользователей. Публичные страницы: главная с данными, <http://localhost:8000/shelters>,
страница приюта, «Как помочь» `/help`, `/privacy`.
Уведомления (этап 12): колокольчик со счётчиком в шапке и раздел «Уведомления» в кабинете
<http://localhost:8000/notifications> — о записи на выгул и её подтверждении, напоминание за сутки, новые заявки и
решения по ним, спасибо за пожертвование, собранный сбор, решение модерации приюта. Те же уведомления уходят письмом.

**Оплата в демо-режиме.** Настоящих платёжных ключей в проекте нет: после «Пожертвовать» открывается учебная
страница банка с кнопками «Оплатить» и «Отказ банка» — карта не нужна, деньги не списываются, а сумма сбора
пересчитывается так же, как при настоящем платеже.
Письма (ссылка для смены пароля, уведомления) в режиме запуска не отправляются, а пишутся в лог:
`docker compose logs app queue` (письма уведомлений отправляет воркер очереди `queue`).

| Логин | Роль | Что посмотреть |
|-------|------|----------------|
| `volunteer` | волонтёр (Айгерим) | записи на выгул, заявки на питомцев, избранное, пожертвования |
| `shelter` | представитель приюта «Дом лап», Алматы (владелец) | питомцы, сборы, слоты и записи приюта |
| `murlyka`, `teplyugol`, `hvostiki` | владельцы приютов в Астане, Шымкенте, Караганде | то же для своих приютов |
| `kotopes` | приют «Котопёс», Актобе — заявка на модерации | кабинет в режиме черновика |
| `admin` | администратор | модерация приютов, пользователи, статистика |

Демо-данные: 4 проверенных приюта и 1 на модерации, 32 питомца, 9 сборов (с пожертвованиями и отчётами),
расписание выгулов на две недели вперёд (весь горизонт записи) и две недели истории. Даты считаются от момента первого запуска.

### То же самое из командной строки

Если удобнее PowerShell или cmd (а также для macOS и Linux) — в папке проекта:

```bash
docker compose up -d --build
```

Остановить:

```bash
docker compose down
```

Полный сброс (удалить базу и загруженные файлы, при следующем запуске демо-данные создадутся заново):

```bash
docker compose down -v
```

### Если что-то пошло не так

- **«Docker Desktop не запущен»** — откройте Docker Desktop и дождитесь «Engine running», затем снова `start.bat`.
- **Порт 8000 занят** другой программой — запустите на другом порту. В PowerShell:

  ```bash
  $env:APP_PORT=8080; docker compose up -d --build
  ```

  и откройте <http://localhost:8080>.
- **Посмотреть, что происходит внутри**:

  ```bash
  docker compose logs app
  ```

- **После обновления кода сайт не изменился** — пересоберите образ: `start.bat` (он всегда запускает
  `docker compose up -d --build`).
- **Открываете сайт с другого устройства** (по IP компьютера в локальной сети) — работает, фото тоже; ссылки в
  письмах и sitemap всё равно ведут на `localhost`.
- Подробный чек-лист и типичные проблемы Windows (WSL 2, виртуализация, прокси, место на диске) —
  [`docs/windows-run.md`](docs/windows-run.md).

## Запасной способ: без Docker (Laravel Herd + SQLite)

Если на компьютере не работает виртуализация и Docker Desktop не запускается.

1. Установите **Laravel Herd for Windows** — <https://herd.laravel.com/windows> (в нём уже есть PHP 8.4,
   Composer и Node.js). PostgreSQL не нужен: база — один файл SQLite.
2. В папке проекта выполните в терминале Herd (PowerShell или cmd) по очереди:

   ```bash
   copy .env.sqlite.example .env
   ```

   ```bash
   composer install
   ```

   ```bash
   php artisan key:generate
   ```

   ```bash
   php -r "touch('database/database.sqlite');"
   ```

   ```bash
   php artisan migrate --seed
   ```

   ```bash
   php artisan storage:link
   ```

   ```bash
   npm install
   ```

   ```bash
   npm run build
   ```

   ```bash
   php artisan serve
   ```

3. Откройте <http://localhost:8000>.

В этом режиме очередь выполняется сразу (`QUEUE_CONNECTION=sync`), отдельный воркер не нужен.
Фоновые задачи (напоминания о выгуле, закрытие сборов по сроку) работают, если во втором окне терминала запущен
планировщик:

```bash
php artisan schedule:work
```

## Если ничего не запускается: демо-макет

Когда не удаётся запустить ни Docker, ни Herd, а сайт нужно показать, — откройте **`mockup/index.html` двойным
щелчком**. Это статическая копия сайта с демо-данными: работает в Chrome, Edge и Firefox без сервера, интернета и
установки чего-либо (протокол `file://`).

- Вверху каждой страницы — плашка «Демо-версия: данные не сохраняются на сервере» и переключатель
  «Гость / Волонтёр / Приют / Админ». Вход — логин `volunteer`, `shelter` или `admin`, пароль любой.
- Работают фильтры, поиск и сортировка каталога; «Помочь сбору» (сумма и полоса прогресса растут), «Записаться на выгул»
  (в слоте занимается место, запись — в «Моих выгулах»), «Хочу забрать» (заявка — в «Моих заявках»), избранное.
- Всё сделанное хранится только в этом браузере; кнопка «Сбросить демо» возвращает исходное состояние.
- Даты слотов и сборов — на момент выгрузки макета. Формы кабинетов приюта и админа показывают подсказку
  «изменения не сохраняются».

Чтобы передать макет по почте или на флешке, упакуйте папку в архив (PowerShell, в папке проекта):

```powershell
Compress-Archive -Path mockup -DestinationPath mockup.zip -Force
```

Получателю — распаковать архив целиком («Извлечь всё») и открыть `index.html`; внутри есть `README.txt` с инструкцией.

Макет собирается из настоящего сайта, чтобы не расходиться с ним. После изменений шаблонов пересоберите его
(нужен запущенный сайт с демо-данными):

```bash
docker compose exec app php artisan mockup:export
```

```bash
docker compose cp app:/var/www/html/mockup ./
```

(в режиме разработки код смонтирован с хоста, вторая команда не нужна). Проверка макета в браузере
(все страницы по `file://` без сети + сценарии): `node tests/browser/mockup.mjs` (нужен Playwright, как ниже).

## Режим разработки

Код монтируется в контейнер с диска, CSS/JS пересобираются на лету (Vite HMR), письма перехватывает Mailpit:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

| Что | Адрес |
|-----|-------|
| Сайт | <http://localhost:8000> |
| Vite dev server | <http://localhost:5173> |
| Mailpit (письма) | <http://localhost:8025> |
| Витрина UI-кита (только в режиме разработки) | <http://localhost:8000/styleguide> |
| PostgreSQL | `localhost:5432`, база `vetmoment`, пользователь `vet_user` / `vet_pass` |

При первом запуске контейнер сам выполнит `composer install` (с dev-пакетами), а сервис `vite` — `npm ci`.

Полезные команды:

```bash
docker compose exec app php artisan test
```

```bash
docker compose exec app ./vendor/bin/pint
```

```bash
docker compose exec app php artisan migrate:fresh --seed
```

```bash
docker compose logs -f app queue scheduler
```

### Как устроен запуск

| Файл | Назначение |
|------|-----------|
| `Dockerfile` | многоэтапная сборка: Composer-зависимости → сборка CSS/JS (Node) → PHP 8.4 + Apache |
| `docker-compose.yml` | режим запуска: `app` (сайт, :8000), `queue` (воркер очереди — письма), `scheduler` (планировщик задач), `db` (PostgreSQL 15, наружу не открыт) |
| `docker-compose.dev.yml` | режим разработки: bind-mount кода, `vite`, `mailpit`, порт БД наружу |
| `docker/start.sh` | точка входа: `.env` из примера, `APP_KEY` (хранится в томе `storage`), ожидание БД, миграции, демо-данные при пустой базе, `storage:link`, кеш конфигурации |
| `start.bat` / `stop.bat` | запуск и остановка на Windows двойным кликом |
| `docker-compose.prod.yml`, `docker/Caddyfile`, `deploy.env.example` | запуск на сервере: домен, HTTPS (Caddy), пароль БД, SMTP, без демо-данных — [`docs/deploy.md`](docs/deploy.md) |
| `.env.example` | настройки для Docker (PostgreSQL) |
| `.env.sqlite.example` | настройки для запуска без Docker (SQLite) |

Переменные, которые можно задать перед запуском: `APP_PORT` (порт сайта, по умолчанию `8000`),
`APP_DEBUG` (`true` — подробные ошибки), `DB_PORT` (порт PostgreSQL в режиме разработки).
Docker Compose берёт их из окружения или из файла `.env` в папке проекта; `APP_ENV` в режиме запуска всегда `production`
(чтобы `.env` от запасного способа не переключил Docker в режим разработки).

Платежи (`config/payments.php`, по умолчанию менять ничего не нужно): `PAYMENT_GATEWAY` — `fake` (демо-банк) или
`cloudpayments_kz` (заготовка драйвера, на реальном API не проверялась; нужны `CLOUDPAYMENTS_PUBLIC_ID` и
`CLOUDPAYMENTS_API_SECRET`, адрес уведомлений — `/payments/webhook/cloudpayments_kz?type=pay|fail|refund`),
`PAYMENT_PENDING_TTL` — через сколько минут неоплаченное пожертвование считается истёкшим (60).

Фоновые задачи (контейнер `scheduler`, список — `routes/console.php`, проверить: `docker compose exec app php artisan schedule:list`):

| Команда | Как часто | Что делает |
|---------|-----------|-----------|
| `app:expire-pending-donations` | каждые 10 мин | неоплаченные пожертвования старше `PAYMENT_PENDING_TTL` → «Срок оплаты истёк» |
| `app:close-expired-campaigns` | каждые 15 мин | идущие сборы с прошедшей датой окончания → «Завершён» |
| `app:send-walk-reminders` | каждые 15 мин | напоминание о подтверждённой прогулке за 24 часа (один раз) |
| `app:expire-unconfirmed-bookings` | каждые 15 мин | записи, не подтверждённые приютом до начала прогулки, → «Отменена» |
| `queue:prune-failed` | раз в сутки | удаляет упавшие задачи очереди старше 14 дней |

SEO и кэш:

- `/sitemap.xml` — публичные анкеты, сборы и приюты (кэш 1 час), `/robots.txt` — отдаётся приложением и закрывает
  кабинеты, вход и служебные страницы. Адреса в них строятся от `APP_URL` — на сервере укажите настоящий домен.
- Главная кэширует цифры проекта и блок приютов на 10 минут. Чтобы увидеть изменения сразу:

```bash
docker compose exec app php artisan cache:clear
```

- Картинка для шаринга (`public/images/og-default.png`) и логотип для писем пересобираются скриптом
  `node design/tools/og-image.mjs` (нужен только при смене айдентики).

## Тесты и проверки

```bash
docker compose exec app php artisan test
```

(в режиме разработки; без Docker — `php artisan test` в папке проекта). Тесты идут на SQLite в памяти, CI
(`.github/workflows/ci.yml`) дополнительно гоняет их на PostgreSQL 15, проверяет стиль (Pint), сборку фронтенда и
запуск `docker compose up` с нуля. Стиль кода:

```bash
docker compose exec app ./vendor/bin/pint --test
```

Браузерная smoke-проверка работающего сайта с демо-данными (обход 45 страниц под всеми ролями: коды ответов, ошибки
консоли и политики CSP, внешние запросы, горизонтальная прокрутка на 360 px; сквозные сценарии «пожертвование → демо-банк»,
«заявка на питомца», «запись на выгул → подтверждение приютом → уведомление → отмена»). Нужны Node.js и Playwright:

```bash
npm i --no-save playwright
```

```bash
npx playwright install chromium
```

```bash
node tests/browser/smoke.mjs
```

Другой адрес — переменная `BASE_URL`, скриншоты 1440 и 390 px в `docs/screenshots/stage-14/` — флаг `--screenshots`.
Сценарии меняют данные (свежая база — `docker compose down -v`); вход ограничен 10 попытками в минуту, поэтому
запускайте не чаще раза в минуту.

## Запуск на сервере

Коротко: `deploy.env` из `deploy.env.example` (домен, пароль БД, почта), затем

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file deploy.env --profile https up -d --build --wait
```

и `php artisan app:create-admin` для первого администратора. Подробно, с обновлением и резервными копиями, —
[`docs/deploy.md`](docs/deploy.md).

## Безопасность

CSRF во всех формах, экранирование вывода, проверка загрузок по содержимому (только JPG/PNG/WebP), политики доступа
на каждый объект, лимиты частоты на вход, регистрацию, формы и webhook, заголовки `Content-Security-Policy`,
`X-Frame-Options`, `X-Content-Type-Options`, HSTS на HTTPS; в `/storage` не выполняется PHP. Секретов в репозитории нет.
Проверка зависимостей:

```bash
docker compose exec app composer audit
```

Подробно — раздел «Безопасность» в [`docs/architecture/overview.md`](docs/architecture/overview.md).

## Соглашения

- Интерфейс только на русском. Валюта — тенге (₸), суммы хранятся в тиынах.
- Телефоны — казахстанские мобильные `+7 7XX XXX XX XX`, хранятся как `+77XXXXXXXXX`
  (нормализация — `App\Support\Phone`, правило валидации — `App\Rules\KazakhPhone`).
- Время в БД — UTC, показывается в `Asia/Almaty` (`config('app.display_timezone')`).
- Код не зависит от СУБД: тесты идут на SQLite, CI дополнительно гоняет их на PostgreSQL 15.
- Интерфейс: дизайн-токены — в `@theme` (`resources/css/app.css`), UI-кит — Blade-компоненты
  `resources/views/components/` (витрина — `/styleguide`), шрифты и иконки — локальные, без CDN.
  Суммы выводятся через `App\Support\Money::format()` (`1 500 ₸`), даты — `App\Support\LocalTime`.

Инструкции для разработки по этапам — [`CLAUDE.md`](CLAUDE.md), заметки по этапам — [`docs/stages/`](docs/stages/).
