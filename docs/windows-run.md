# Приёмка запуска на Windows

Этап 14, пункт 3 плана: пройти сценарий «чистый Windows 10/11 + Docker Desktop → `start.bat` → работающий сайт
с демо-данными» и запасной сценарий «Herd + SQLite» буквально по README и записать шаги и найденные проблемы.

**Реальной Windows-машины у агента нет.** Ниже — что проверено в окружении агента (Linux), какие проблемы найдены
и исправлены, и чек-лист для прохождения на вашем ПК. Если на Windows ничего не запустится — откройте демо-макет
(этап 15, `mockup/index.html` двойным кликом; будет готов на следующем этапе).

## 1. Что проверено в окружении агента (2026-11-23)

Окружение: Linux, Docker Engine 29.9, Docker Compose 5.6, Chromium (Playwright).

| Проверка | Как | Результат |
|----------|-----|-----------|

(песочница не пускает `npm ci` из контейнера).

## 2. Найденные проблемы и что сделано

| # | Проблема | Как проявлялась бы на Windows | Исправление |
|---|----------|-------------------------------|-------------|
| 1 | Docker Compose подставляет `${APP_ENV}` из файла `.env` в папке проекта | Пользователь сначала пробует запасной путь (Herd создаёт `.env` с `APP_ENV=local`), потом запускает `start.bat` — сайт в Docker работает в режиме разработки: витрина UI-кита открыта, ленивые запросы к БД роняют страницу ошибкой | `APP_ENV: production` задан в `docker-compose.yml` жёстко, `local` — только в `docker-compose.dev.yml` |
| 2 | Адреса фото строились от `APP_URL` (`http://localhost:8000/storage/...`) | Сайт открыт по `http://127.0.0.1:8000`, по IP в локальной сети (показ с телефона) или Herd запущен на другом порту (`php artisan serve --port=8080`) — все фото питомцев битые | Адрес диска `public` — относительный `/storage` (`config/filesystems.php`); абсолютный для Open Graph строит `Seo::absolute()` |
| 3 | В README команда `type nul > database\database.sqlite` | В PowerShell (терминал Herd по умолчанию) — ошибка «Cannot find path …\nul» | Заменена на `php -r "touch('database/database.sqlite');"` — работает и в PowerShell, и в cmd |
| 4 | 48 известных уязвимостей в зависимостях (`composer audit`) | — | `composer update`, теперь 0 |

## 3. Чек-лист для проверки на вашем ПК

Отмечайте результат и, если что-то пошло не так, пришлите текст ошибки и вывод `docker compose logs app`.

### Сценарий A. Docker Desktop (основной)

Подготовка: Windows 10 22H2 или Windows 11, включена виртуализация (Диспетчер задач → Производительность → ЦП →
«Виртуализация: включено»), свободно 6 ГБ на диске, интернет (первый запуск качает ~1,5 ГБ образов и пакетов).

| # | Шаг | Ожидаемый результат | ✓ |
|---|-----|---------------------|---|
| A1 | Установить Docker Desktop с <https://www.docker.com/products/docker-desktop/>, галочка «Use WSL 2», перезагрузка | После входа в Windows Docker Desktop стартует, внизу слева «Engine running» | ☐ |
| A2 | GitHub → Code → Download ZIP, распаковать (например, в `C:\Projects\VetMoment`) | В папке есть `start.bat`, `docker-compose.yml` | ☐ |
| A3 | Двойной клик по `start.bat` | Окно с «[VetMoment] Собираем и запускаем контейнеры…», идёт сборка (5–10 минут в первый раз) | ☐ |
| A4 | Дождаться конца | «Готово! Сайт: http://localhost:8000», браузер открывается сам | ☐ |
| A5 | Главная | Питомцы недели с фото, сборы с прогрессом, слоты на неделю, приюты-партнёры | ☐ |
| A6 | Войти `volunteer` / `password` → «Запись на выгул» → выбрать время → записаться | Открывается подтверждение записи, в колокольчике у приюта (`shelter`) — новое уведомление | ☐ |
| A7 | Выйти, открыть любой сбор → «Пожертвовать» → 1 500 → почта → «Оплатить» | «Спасибо!», сумма сбора выросла | ☐ |
| A8 | Войти `admin` / `password` | Админка со статистикой | ☐ |
| A9 | Двойной клик по `stop.bat`, затем снова `start.bat` | Запуск за секунды, данные (запись из A6) на месте | ☐ |
| A10 | Перезагрузить ПК, запустить `start.bat`, не открывая Docker Desktop вручную | Скрипт сам запускает Docker Desktop, ждёт и поднимает сайт | ☐ |

Дополнительно (если есть время):

- Занятый порт: запустить `start.bat` при занятом 8000 (например, `python -m http.server 8000`) — должно быть понятное
  сообщение со ссылкой на README; в PowerShell `$env:APP_PORT=8080; docker compose up -d --build` → сайт на :8080 с фото.
- Путь с пробелами и кириллицей (`C:\Users\Имя\Мои проекты\VetMoment`) — `start.bat` должен работать так же.
- Сайт с телефона в той же сети: `http://<IP компьютера>:8000` (брандмауэр Windows может спросить разрешение) — фото видны.

### Сценарий B. Laravel Herd + SQLite (запасной)

| # | Шаг | Ожидаемый результат | ✓ |
|---|-----|---------------------|---|
| B1 | Установить Laravel Herd for Windows (<https://herd.laravel.com/windows>), в нём PHP 8.4 | `php -v` в терминале → 8.4.x; `php -m` содержит `fileinfo`, `gd`, `pdo_sqlite` | ☐ |
| B2 | В папке проекта выполнить команды README «Запасной способ» по порядку | Каждая команда без ошибок; `migrate --seed` пишет `DemoSeeder … DONE` | ☐ |
| B3 | `php artisan serve` → <http://localhost:8000> | Главная с фото, вход `volunteer` / `password` работает | ☐ |
| B4 | Запись на выгул и пожертвование, как A6–A7 | Работают; письма — в `storage\logs\laravel.log` | ☐ |

### Если что-то не получилось

| Симптом | Что сделать |
|---------|-------------|
| «Docker не найден» | Установить Docker Desktop, перезагрузить ПК |
| Docker Desktop: «WSL 2 installation is incomplete» / «Virtualization support not detected» | `wsl --update` в PowerShell от администратора; включить виртуализацию (Intel VT-x / AMD-V) в BIOS |
| Сборка падает на скачивании (`TLS`, `timeout`) | Корпоративный прокси или антивирус с проверкой HTTPS: попробовать с домашней сети или указать прокси в Docker Desktop → Settings → Resources → Proxies |
| «no space left on device» | Docker Desktop → Troubleshoot → Clean / Purge data, освободить место |
| Сайт открылся без стилей | Сообщить: в образе не собрались ассеты (`docker compose logs app`) |
| Ничего не помогает | Демо-макет `mockup/index.html` (этап 15) |
