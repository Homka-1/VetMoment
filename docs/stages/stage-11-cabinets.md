# Этап 11. Личные кабинеты

Дата: 2026-11-10 · Статус: ✅ готов

## Цель этапа
Кабинеты волонтёра, приюта и администратора по макетам 09–11, а также публичные страницы без своего этапа:
главная с данными, приюты, «Как помочь», политика.

## Что сделано
- **Волонтёр**: обзор `/cabinet` (ближайший выгул, последняя заявка, пожертвования за год, избранное; пустые
  состояния с действием); «Мои заявки» `/cabinet/applications` (вкладки «Активные» / «Закрытые», ответ приюта,
  «Отозвать заявку»); профиль `/cabinet/profile` — имя, телефон (нормализуется), почта и отдельная форма смены
  пароля (нужен текущий). Профиль общий для всех ролей. В меню — «Стать приютом» для волонтёра без приюта.
- **Приют**: сводка `/shelter` (макет 10: ищут дом / новые заявки / выгулы сегодня / собрано за месяц, записи на
  сегодня с кнопками решения — переиспользованы партиалы этапа 10, новые заявки, баннер модерации); профиль приюта
  `/shelter/profile` (контакты, описание, правила выгула, логотип со сменой и удалением) — только владелец.
- **Администратор**: статистика `/admin` (месяц на выбор: пристроено с дельтой, собрано, прогулки, неявки в %,
  столбцы «по неделям», итоги за всё время, плашка про очередь модерации); очередь приютов `/admin/shelters`
  (вкладки, «Одобрить», «Отклонить» и «Заблокировать» с причиной в модалке, «Разблокировать»); анкеты
  `/admin/pets` и сборы `/admin/campaigns` с «Скрыть» / «Вернуть» (`PetPolicy::hide`, `CampaignPolicy::hide`);
  заявки `/admin/applications` (только просмотр); пользователи `/admin/users` (поиск, роль, «только
  заблокированные», блокировка).
- **Блокировка пользователя** (`UserModeration`, `UserPolicy`): будущие активные записи на выгул отменяются
  (`cancelled_by = system`), места возвращаются в слоты — долг этапа 6.
- **Публичные**: главная (`HomeController`: питомцы дольше всех в поиске, сборы, слоты на 7 дней, приюты, цифры
  проекта — `PlatformStats`), `/shelters` (фильтр по городу), `/shelters/{slug}` (макет 07: контакты, правила выгула,
  питомцы, сборы, ближайшие выгулы, отчёты; неодобренный приют — 404, своему приюту и админу — с баннером и
  `noindex`), `/help` (три пути, FAQ, «стать партнёром»), `/privacy`.
- Компоненты: `<x-stat>` (цифра сводки), `<x-slot-tile>` (слот-ссылка для главной и приюта). `Money::compact()`
  («2,1 млн ₸»).
- Заглушки кабинетов (`CabinetStubController`, `cabinet/stub`) удалены.
- Тесты: +45 (всего 387): кабинет волонтёра, сводка и профиль приюта (права владельца, логотип, поля, которые нельзя
  менять), вся админка, публичные страницы, `Money::compact`.

## Принятые решения
- **Скрытие без причины**: в таблицах `pets` и `donation_campaigns` нет поля для причины, схему этапа 5 не меняли;
  «Скрыть» — переключатель `is_hidden`, приют по-прежнему видит свою анкету с баннером.
- **Профиль приюта — только владелец** (`ShelterPolicy::update`); пункта в меню у остальных сотрудников нет.
  БИН/ИИН и статус модерации в форме не меняются.
- **Суммы по месяцам считаются по `paid_at`**, а не `created_at` — это момент подтверждения платежа.
- **Статистика без SQL-функций дат**: недели группируются в PHP (код работает на PostgreSQL и SQLite).
- **Админ не блокирует админов и уже заблокированных** (`UserPolicy`), блокировка — через модалку без причины.
- **Столбцы статистики — HTML, а не библиотека графиков**: список `<ol>` с подписями для скринридера, без JS.
- **Страница приюта показывает питомцев из каталога** (ищут дом), чтобы «Все N» совпадало с каталогом.
- **Тесты используют необычные имена** («Марат Тестовый»): фабрики генерируют правдоподобные русские имена, и
  короткие «Ольга Ким» случайно совпадали.

## Отклонения от плана
- **Без уведомлений и колокольчика со счётчиком** в меню кабинета и **без бейджей-счётчиков** у пунктов меню (есть
  на макетах) — уведомления этап 12; добавить счётчики можно тогда же одним запросом.
- **«Сотрудники» приюта** (приглашение, удаление) не сделаны: в плане этапа их не было, в MVP один приют на пользователя.
- **Админ-раздел пожертвований** не делался: план просил заявки, анкеты, пользователей, статистику.
- Страница приюта — одним экраном без вкладок макета (о приюте, питомцы, сборы, отчёты, выгул идут секциями).
- Загрузка аватара пользователя не сделана (поле `avatar_path` есть) — не требовалась макетами.
- Макет админки с файлами заявки («3 файла») не воспроизведён: файлов заявки нет в данных.

```bash
docker compose up -d --build

```

## Известные проблемы и долги
- Таблицы кабинетов на телефоне прокручиваются по горизонтали (решение этапа 7).
- `AppBootTest` теперь требует БД (главная читает данные) — добавлен `RefreshDatabase`.
- Главная считает запросы на каждый показ — кэш главной запланирован на этап 13.
- Откладывается на этап 12: уведомление волонтёру об отмене записи при блокировке; уведомление приюту о решении
  модерации.
