# Этап 15. Демо-макет без зависимостей (запасной вариант)

Дата: 2026-11-24 · Статус: ✅ готов

## Цель этапа
Статическая кликабельная версия сайта «на крайний случай»: `mockup/index.html` открывается двойным щелчком в любом
браузере, без сервера, интернета и установки, и выглядит как основная версия.

## Что сделано
- **Выгрузка из настоящего сайта** — команда `php artisan mockup:export` (задача 4 плана): обход страниц в ширину под
  ролями «гость / волонтёр / приют / админ» от стартовых адресов по ссылкам, рендер тем же HTTP-ядром Laravel (без
  веб-сервера, каждый запрос — с чистой сессией и своим пользователем), перепись в статику:
  - все страницы — плоско в `mockup/`: `/` → `index.html`, `/pets/bublik-21ke` → `pets-bublik-21ke.html`,
    `/walks?shelter=dom` → `walks--shelter-dom.html`; общие для ролей страницы — `notifications--as-shelter.html`;
  - ссылки, картинки, иконки сайта — относительные; редиректы (уведомление → страница, слот, куда волонтёр уже записан →
    его запись) разрешаются в файл цели; ссылки на страницы, которых нет в макете (CSV, `.ics`, оплата), — `#` с подсказкой;
  - сборка Vite: `app.css` (шрифты рядом, `url()` относительные) и `app.js` — как **обычный скрипт** в замыкании
    (ES-модули не работают по `file://`); CSRF-токены и `<script type="module">` убраны;
  - формы: GET — обрабатывает JS (поиск файла по параметрам), POST — `data-demo-action` с исходным адресом;
  - каталог питомцев — **все анкеты на одной странице** (склейка страниц пагинации) + скрытое пустое состояние;
  - данные для JS — `assets/data.js` (`window.DEMO_DATA`): роли, шапки/меню/подвал каждой роли, карта адресов,
    питомцы (атрибуты фильтров, миниатюра, карточка), сборы, слоты, готовые бейджи и тосты из Blade-компонентов.
- **Логика макета** — `resources/mockup/demo.js` (копируется в `mockup/assets/`), без модулей, `fetch` и внешних запросов:
  - плашка «**Демо-версия:** данные не сохраняются на сервере» с переключателем ролей и «Сбросить демо» на каждой странице;
  - вход по логину (`volunteer` / `shelter` / `admin`, пароль любой, подсказка над формой), регистрация → волонтёр,
    выход; гость на странице кабинета отправляется на вход и возвращается обратно (`login.html?next=…`);
    на публичных страницах подменяются шапка, мобильное меню и подвал вошедшей роли;
  - «Пожертвовать» — проверка суммы 200 ₸ – 5 000 000 ₸, email и согласия; растут сумма, процент, полоса и число
    помогших во всех карточках сбора; у вошедшего — строка в «Моих пожертвованиях» и итог;
  - «Записаться на выгул» — выбор слота → страница слота → запись; место занимается в календаре и плитках
    («Осталось 1 место» → «Мест нет», радиокнопка отключается), строка в «Моих выгулах», защита от повторной записи;
  - «Хочу забрать / Взять под опеку» — заявка в «Моих заявках» (с «Отозвать заявку»); избранное — сердечко везде
    и страница «Избранное»;
  - фильтры, поиск по кличке и сортировка каталога по `data.js`, параметры из адреса (`pets.html?species[]=cat`);
  - прочие формы (кабинеты приюта и админа) — тост «Демо-версия: изменения не сохраняются» с названием действия;
  - состояние — `localStorage` + копия в `window.name` (запасной путь, если браузер не делит хранилище между
    `file://`-страницами).
- **Стили плашки** — `resources/mockup/demo.css`, только токены темы; на телефоне подпись «Смотреть как» скрыта для
  глаз, «Сбросить демо» → «Сбросить».
- **Хуки в Blade** (на сайт не влияют): `data-campaign*` / `data-progress-*` в карточке, сводке и полосе сбора,
  `data-slot-note` у слота и плитки слота, `data-pet-catalog`, `data-catalog-empty`, `data-catalog-pagination`,
  `data-favorites-list`.
- Сгенерированный макет `mockup/`: 356 страниц (с `404.html`), ~20 МБ, в ZIP ≈ 3,8 МБ; `mockup/README.txt` — инструкция
  для получателя (CRLF, читается Блокнотом).
- Проверка `tests/browser/mockup.mjs`, тесты `PageMapTest` (5) и `MockupExportTest` (2), раздел README
  «Если ничего не запускается: демо-макет».

## Принятые решения
- **Выгрузка отрендеренных страниц, а не ручная вёрстка** — макет совпадает с сайтом пиксель в пиксель и пересобирается
  одной командой после изменений шаблонов. Рендер внутри приложения (HTTP-ядро), а не обход по HTTP — не нужен вход
  с лимитом попыток и сессии, команда работает и в образе без браузера.
- **Одна страница на анкету / сбор / слот** (`pets-<slug>.html`), а не `pet.html?id=3` из примера плана: страница —
  настоящий HTML сайта, без шаблонизации в JS. Query остаётся только у каталога (фильтры в JS).
- **Публичные страницы — от имени гостя, кабинеты — от своей роли**; для вошедшего на публичной странице JS подменяет
  шапку, меню и подвал. Открытие страницы чужой роли (приют → запись на выгул) переключает роль с подсказкой, а не
  показывает 403 — для демонстрации так удобнее.
- **Ограничение обхода**: недели календарей — от −1 до +3 от даты выгрузки, страницы списков — до 6-й, параметры, которые
  не меняют страницу (`slot` у выгула, `pet` у слота, `page=1`), отбрасываются. Без этого календарь кабинета приюта
  давал бесконечный обход (561 страница недель на первой попытке).
- **Строки кабинета, которые добавляет JS, собраны из классов тех же шаблонов**, а бейджи, миниатюры, кнопки и тосты —
  отрендерены Blade-компонентами в `data.js`: классы гарантированно есть в CSS (`demo.js` к тому же попадает в `@source`).
- **Пожертвование без демо-банка**: в макете сразу «Спасибо! Платёж прошёл» тостом на странице сбора — промежуточная
  страница банка без сервера ничего бы не показала.
- **Цвет плашки — `ink-900`, без жёлтого**: жёлтый в айдентике — только деньги (решение этапа 2); выбранная роль —
  белая таблетка, фокус — светлое кольцо `sky-200` (контраст на тёмном фоне).

## Отклонения от плана
- **`mockup.zip` в репозиторий не положен**: он дублировал бы папку (≈ 3,8 МБ на каждую пересборку в истории git).
  Вместо него — команда PowerShell `Compress-Archive` в README и `README.txt` внутри макета. Если архив нужен готовым —
  сделаю отдельным коммитом или релизом.
- Адреса страниц — `pets-<slug>.html` вместо `pet.html?id=N` (см. решения).
- Сверх плана: копия состояния в `window.name`, страница `404.html`, хуки `data-*` в Blade, unit- и feature-тесты экспорта.

## Как проверить
```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec app php artisan mockup:export
npm i --no-save playwright && node tests/browser/mockup.mjs --screenshots
docker run --rm -v "$PWD":/app -w /app php:8.4-cli php -d memory_limit=1G vendor/bin/phpunit
./vendor/bin/pint --test
npm run build
```
Вручную: дважды щёлкнуть `mockup/index.html`.

## Известные проблемы и долги
- **Не проверено в Edge и Firefox на Windows** (нет машины) — проверен Chromium; код без модулей и `fetch`, для Firefox
  предусмотрен запасной путь состояния через `window.name`.
- **Даты замораживаются в момент выгрузки**: слот «завтра» через месяц всё ещё выглядит предстоящим. Перед показом
  макет лучше пересобрать.
- Счётчики во вкладках кабинета («Предстоящие 3») и число непрочитанных уведомлений не учитывают действия в демо.
- Заявка не меняет кнопку на карточке питомца («Заявка отправлена»); статусы в кабинете приюта не меняются от действий
  волонтёра — роли не связаны общим «сервером».
- Размер ~20 МБ (356 HTML по 30–130 КБ, в каждом встроенный спрайт иконок): `<use href="icons.svg#…">` из внешнего
  файла по `file://` не работает в Chrome.
- Найдено попутно (не исправлялось, вне этапа): `docker compose exec app php artisan test` в режиме разработки идёт
  **на PostgreSQL dev-базы** (переменные контейнера перекрывают `DB_*` из `phpunit.xml`), `RefreshDatabase` стирает
  демо-данные и ~120 тестов падают. Надёжный путь — `php:8.4-cli` с SQLite (как выше) или `force="true"` для `DB_*` в
  `phpunit.xml` (но тогда CI-job на PostgreSQL нужно перевести на отдельный конфиг). В `php:8.4-cli` при лимите памяти
  128 МБ набор падает на нехватке памяти — нужен `-d memory_limit=1G`.

## Что важно знать на следующем этапе
- Это последний этап плана. Изменили шаблоны → пересоберите макет: `php artisan mockup:export` (в режиме разработки
  пишет прямо в `mockup/`), затем `node tests/browser/mockup.mjs`.
- Новый интерактив на сайте, который должен работать в макете, — через `data-*` хуки и обработчик в `demo.js`
  (по `data-demo-action` — исходному адресу POST-формы).
- Новые страницы попадают в макет сами, если на них есть ссылка; страницы без ссылок (как слоты) — в `SEEDS` или
  отдельным циклом в `MockupExporter::crawl()`.
