# Этап 3. Макеты ключевых экранов

Дата: 2026-11-03 · Статус: ✅ готов (ждёт утверждения пользователем)

## Цель этапа
Нарисовать макеты всех ключевых страниц (desktop 1440 и mobile 390) с состояниями и схемой переходов,
чтобы вёрстка этапов 7–13 шла по готовому дизайну.

## Что сделано
- 12 SVG-файлов в `design/screens/` с 42 артбордами и PNG-превью в `design/screens/png/`:
  главная, каталог, карточка питомца и заявка, сборы, страница сбора с пожертвованием и результатами платежа,
  запись на выгул (неделя слотов, подтверждение, успех), страница приюта, вход/регистрация,
  кабинет волонтёра, кабинет приюта (сводка, питомцы, слоты), админ-модерация и статистика,
  ошибки 404/500 и набор пустых/загрузочных/успешных состояний.
- У каждого экрана есть mobile-версия; состояния: пустые, ошибки, загрузка, успех, модерация.
- `docs/design/screens.md`: состав артбордов, покрытие состояний, сетка, решения и схема переходов (Mermaid).
- Генератор расширен: `design/tools/screens.js`, `screens2.js`, `screens3.js` (флаг `--screens` в `build.mjs`
  для быстрой пересборки только экранов). `petCard`/`campaignCard` получили параметр ширины;
  UI-кит при этом не изменился (кроме подписи о контейнере).

## Принятые решения
- **Герой главной — портрет питомца с большой адресной биркой** (кличка, возраст, приют): мотив айдентики
  стал главным элементом страницы; цифры проекта — отдельная спокойная плашка ниже.
- **Контейнер 1280** вместо 1240: ровно 4 карточки питомца по 296 + 3 × 32.
- **Кабинеты:** боковое меню 256 px слева + таблицы; на телефоне меню кабинета — горизонтальные «таблетки»
  или список разделов, таблицы превращаются в карточки с теми же действиями.
- **Каталог на телефоне** — 2 колонки компактных карточек (`petMini`), фильтры — нижний лист.
- **Запись на выгул — 3 шага** (приют → время → подтверждение); выбор приюта на шаге 2 остаётся
  редактируемым, чтобы не возвращаться назад. Выбор собаки — на шаге подтверждения (необязателен,
  занятые собаки неактивны).
- **Пожертвование — форма прямо на странице сбора** (липкая колонка справа на desktop, секция + липкая
  кнопка на mobile), отдельная страница `/campaigns/{slug}/donate` — тот же блок без описания.
- **Результат платежа** — три состояния: оплачено, ожидание (страница обновляется сама), ошибка с причиной.
- **Модерация приюта** видна сотрудникам: бейдж в меню кабинета и баннер над списком питомцев.
- Макеты — без реальных фото: портреты-иллюстрации остаются заглушками, на этапе 8 их заменят фото из сидера.

## Отклонения от плана
- Токен `layout.container` изменён (1240 → 1280) — см. выше.
- Добавлены экраны сверх списка: заявка на питомца, результаты платежа, статистика админки, ошибки 404/500.
- Не нарисованы отдельно второстепенные страницы (список приютов, `/help`, профиль, уведомления, формы
  кабинета приюта и др.) — они собираются из тех же блоков; перечень в `docs/design/screens.md`, раздел 4.

## Как проверить
Открыть PNG в `design/screens/png/` (или SVG в браузере/Illustrator). Пересобрать (нужны Node, Playwright, Python + fonttools):
```bash
node design/tools/build.mjs --screens
```
Код приложения не менялся — тесты, Pint и `npm run build` не требуются.

## Известные проблемы и долги
- Липкие панели на mobile показаны в конце страницы, а не поверх первого экрана (в SVG нет прокрутки).
- Горизонтально прокручиваемые ряды (карусель питомцев на главной, вкладки кабинета) обрезаны краем артборда — так и задумано.
- Тёмная тема не проектировалась.
- SVG тяжёлые (8 МБ на всё вместе с PNG) — портреты повторяются в каждой карточке.

## Что важно знать на следующем этапе
- Этап 4 (инициализация проекта) с дизайном не связан; макеты понадобятся с этапа 7.
- Этап 7: контейнер 1280 (`max-w` из `@theme`), шапки desktop 76 / mobile 64, боковое меню кабинета 256,
  таблицы кабинетов (шапка 44, строки 68–80) — сделать Blade-компонентами (`x-table`, `x-cabinet-layout`, `x-sticky-bar`).
- Этап 5: в сидер нужны данные как на макетах — 4 приюта (Алматы, Астана, Шымкент, Караганда),
  питомцы с чертами характера и здоровьем, сборы со сметой и отчётами, слоты на неделю вперёд.
- Этап 10: календарь недели — 7 колонок по 168 px; пустой день — пунктирная плашка «Выгула нет»;
  на mobile — лента дней с точками-индикаторами.
- Нужно решение пользователя: **утвердить макеты** (и при желании — название VetMoment, вопрос из этапа 2).

## Дополнение (2026-11-04): сборка в Adobe Illustrator

По запросу пользователя добавлен JSX-скрипт для Illustrator — `design/illustrator/VetMoment-to-AI.jsx`
(инструкция — `design/illustrator/README.md`). Он открывает подготовленные SVG, создаёт монтажную область
на каждый артборд (16 файлов, 50 областей), раскладывает артборды по слоям и сохраняет `.ai` в `design/source/`.
- Данные для скрипта генерирует `design/tools/illustrator.mjs` (вызывается из `build.mjs`): SVG без SVG 2-конструкций
  (`<use>` → группы, `feDropShadow` → фильтр SVG 1.1), шрифты по PostScript-именам, `manifest.js` с границами артбордов.
- Для установки в систему добавлены статические TTF `design/fonts/desktop/` (Golos Text, Unbounded; OFL).
- Проверено: рендер подготовленных SVG совпадает с исходными (расхождение 0,02–0,4% — сглаживание текста);
  скрипт проходит разбор как ES3 и прогон на имитации API Illustrator. В самом Illustrator не запускался.
