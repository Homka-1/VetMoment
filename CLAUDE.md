# CLAUDE.md — инструкции для агента

Проект **VetMoment** — сервис помощи бездомным животным и приютам (тема 79):
**анкеты питомцев, сбор пожертвований, запись на выгул**.
Стек: Laravel 13 (PHP 8.4), Blade, Tailwind CSS 4 + Vite, PostgreSQL 15, Docker Compose.
Язык интерфейса, документации, заметок и коммитов — **русский**.

## 1. Главное правило: работа строго по этапам

План — в [`docs/PLAN.md`](docs/PLAN.md). Разработка идёт **как с нуля**, этап за этапом.

1. **Выполняй ровно один этап за раз.** Не начинай следующий этап, не делай «заодно» задачи из
   будущих этапов. Если что-то из будущего этапа нужно прямо сейчас — опиши это в заметке,
   а не реализуй.
2. **Следующий этап — только по команде пользователя** («следующий этап», «этап N», «продолжай»
   и т.п.). Закончив этап — остановись, кратко отчитайся и жди команды. Не спрашивай
   «начать ли следующий этап?» в виде действия — просто сообщи, какой этап следующий.
3. Если пользователь называет конкретный этап, а предыдущие не завершены — предупреди об этом
   и уточни, прежде чем начинать.

### Перед началом этапа (обязательно)
1. Прочитай `docs/PLAN.md` — раздел текущего этапа и таблицу статусов.
2. Прочитай **все** заметки предыдущих этапов в `docs/stages/` (`stage-00-*.md`, `stage-01-*.md`, …),
   особенно разделы «Принятые решения», «Отклонения от плана», «Что важно знать на следующем этапе».
3. Прочитай артефакты, на которые ссылаются заметки (например, `design/tokens.json`,
   `docs/product/*.md`), если они относятся к текущему этапу.
4. Поставь этапу статус `🟡 в работе` в таблице `docs/PLAN.md`.

### По завершении этапа (обязательно)
1. Создай заметку `docs/stages/stage-NN-<slug>.md` по шаблону `docs/stages/_TEMPLATE.md`
   (NN — номер с ведущим нулём, slug — латиницей, например `stage-02-design-concept.md`).
2. Обнови статус этапа в `docs/PLAN.md` на `✅ готов`. Если план пришлось скорректировать —
   поправь раздел будущих этапов и опиши изменение в заметке.
3. Прогони проверки, применимые к этапу (см. раздел 5).
4. Сделай коммит (один или несколько) с префиксом этапа: `Этап N: <что сделано>`, запушь
   в рабочую ветку.
5. Ответь пользователю коротко: что сделано, где заметка, что требует его решения/утверждения,
   какой этап следующий. **Остановись.**

## 2. Фронтенд и дизайн: плагин `frontend-design`

- Для **любой** работы с UI — макеты (этапы 2–3), вёрстка, Blade-шаблоны, CSS/Tailwind, JS
  интерфейса (этапы 7–11, 13) — **сначала вызови скилл `frontend-design:frontend-design`**
  (инструмент Skill) и следуй его рекомендациям. Делай это в начале каждого этапа с UI-задачами.
- Визуальный источник истины — утверждённые артефакты этапов 2–3: `design/tokens.json`,
  `design/ui-kit.svg`, `design/screens/*`. Вёрстка должна им соответствовать; отступления
  фиксируй в заметке этапа.
- Цвета, шрифты, радиусы, тени — только через токены в `@theme` (`resources/css/app.css`),
  без «магических» значений в шаблонах.
- Повторяющиеся элементы — Blade-компоненты в `resources/views/components/`, а не копипаста утилит.
- Mobile first, адаптив 360–1920 px, доступность WCAG AA (контраст, фокус, `alt`, `aria-*`, labels).
- После вёрстки страницы проверяй её в браузере (Playwright/Chromium предустановлен, см. ниже)
  и делай скриншоты desktop (1440) и mobile (390) в `docs/screenshots/stage-NN/`.

### Макеты «как в Adobe Illustrator» (этапы 2–3)
Illustrator в окружении недоступен. Макеты создаются как **SVG с artboard-структурой**
(отдельные `<g id="artboard-...">`, именованные слои, текст — текстом, не кривыми), чтобы их можно
было открыть и доработать в Illustrator/Figma/Inkscape. К каждому SVG — PNG-превью
(рендер через Playwright) в `design/**/png/`. Исходники `.ai` от пользователя, если появятся,
лежат в `design/source/` — они главнее SVG.

## 3. Обязательное требование: простой запуск на Windows

Итоговый проект должен запускаться на Windows 10/11, где установлен **только Docker Desktop**:
`start.bat` (или `docker compose up -d --build`) → `http://localhost:8000` с демо-данными, без ручных шагов.
Подробности — раздел «Сквозное требование» в `docs/PLAN.md`. На каждом этапе:

- Не добавляй зависимостей, которые придётся ставить на хост (PHP, Node, Composer, СУБД, утилиты).
  Всё, что нужно для запуска, собирается внутри Docker-образа.
- Режим по умолчанию (`docker-compose.yml`) — запуск без bind-mount и без Vite dev server;
  разработка — через `docker-compose.dev.yml`.
- Первый запуск полностью автоматический (`.env`, `APP_KEY`, миграции, сид, `storage:link` — в `start.sh`).
- Код независим от СУБД: должен работать и на PostgreSQL, и на SQLite (запасной путь — Laravel Herd + SQLite).
  Никаких pgsql-специфичных типов/операторов (`ILIKE`, JSONB-операторы, массивы).
- Shell-скрипты — LF, `.bat` — CRLF; не используй пути и команды, специфичные для Linux, в инструкциях
  для пользователя (давай команды для PowerShell/cmd).
- Если изменение влияет на запуск (новый сервис, переменная окружения, порт, шаг установки) —
  обнови README и упомяни это в заметке этапа.

## 4. Структура и соглашения

```
app/Enums/            PHP-enums статусов и ролей (PetStatus, BookingStatus, Role, ...)
app/Models/           Eloquent-модели
app/Http/Controllers/ тонкие контроллеры (по разделам: Pets, Donations, Walks, Cabinet/*, Admin/*)
app/Http/Requests/    Form Requests — вся валидация здесь
app/Policies/         права доступа
app/Services/         бизнес-логика (бронирование выгулов, платежи, пересчёт сборов)
app/Support/          утилиты (нормализация телефона и т.п.)
resources/views/components/  UI-кит в Blade
design/               макеты, токены, айдентика
docs/PLAN.md          план и статусы этапов
docs/stages/          заметки по этапам (читать перед каждым этапом!)
docs/product/, docs/design/, docs/architecture/  артефакты этапов
```

- Деньги храним в **копейках** (`unsignedBigInteger`), выводим через хелпер форматирования.
- Даты/время — в `Europe/Moscow` для отображения, в БД — UTC.
- Статусы — PHP backed enums + касты в моделях, не «голые» строки.
- Никаких реальных платёжных ключей в репозитории; по умолчанию `FakePaymentGateway`.
- Не коммить `.env`, `vendor/`, `node_modules/`, `public/build/`.

## 5. Команды и проверки

```bash
docker compose up -d --build          # режим запуска (как у пользователя на Windows), app :8000
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d   # разработка: bind-mount + Vite :5173
docker compose exec app php artisan migrate --seed
docker compose exec app php artisan test
docker compose exec app ./vendor/bin/pint --test
npm run build
```

Если Docker недоступен в окружении агента — используй локальные `php artisan test` (SQLite in-memory
через `phpunit.xml`), `./vendor/bin/pint --test`, `npm run build`. Что не удалось проверить —
честно укажи в заметке этапа.

Минимум перед коммитом этапа с кодом: тесты зелёные, Pint без замечаний, `npm run build` проходит.

## 6. Git

- Коммиты небольшие и осмысленные, сообщение на русском с префиксом `Этап N:`.
